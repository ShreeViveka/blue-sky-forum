# Supabase Setup Guide

This guide walks you through setting up a Supabase project, creating the necessary database tables, enabling security policies, and loading initial seed data.

---

## 1. Create a Supabase Project

1. Go to [supabase.com](https://supabase.com) and sign up or sign in.
2. Click **New Project** and select your organization.
3. Enter a project name (e.g., `BSF Club Website`), set a database password, select a region, and click **Create new project**.
4. Wait for the project to provision (usually takes 1-2 minutes).
5. Once ready, go to **Project Settings** -> **API** in the sidebar.
6. Copy your **Project URL** and your **anon public API key**.
7. Paste these values into the `.env` file at the root of your project:
   ```env
   VITE_SUPABASE_URL=https://your-project-id.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
   ```

## 2. Set Up Database Schema & Policies

1. In your Supabase Dashboard, click on **SQL Editor** in the left navigation sidebar.
2. Click **New Query** to open a blank SQL sheet.
3. Copy and paste the entire SQL block below into the editor:

```sql
-- -------------------------------------------------------------
-- 1. Magazines Table
-- -------------------------------------------------------------
CREATE TABLE public.magazines (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title text NOT NULL,
    year integer NOT NULL,
    month text NOT NULL,
    cover_image text DEFAULT 'https://images.unsplash.com/photo-1518709268805-4e9042af9f23',
    pdf_url text,
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- Enable Row Level Security (RLS)
ALTER TABLE public.magazines ENABLE ROW LEVEL SECURITY;

-- RLS Policies
CREATE POLICY "Allow public read access for magazines" 
    ON public.magazines FOR SELECT TO public USING (true);

CREATE POLICY "Allow authenticated admin writes for magazines" 
    ON public.magazines FOR ALL TO authenticated USING (true);


-- -------------------------------------------------------------
-- 2. Words Table
-- -------------------------------------------------------------
CREATE TABLE public.words (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    word text NOT NULL,
    meaning text NOT NULL,
    example text DEFAULT 'A fortunate stroke of serendipity.',
    pdf_url text,
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- Enable Row Level Security (RLS)
ALTER TABLE public.words ENABLE ROW LEVEL SECURITY;

-- RLS Policies
CREATE POLICY "Allow public read access for words" 
    ON public.words FOR SELECT TO public USING (true);

CREATE POLICY "Allow authenticated admin writes for words" 
    ON public.words FOR ALL TO authenticated USING (true);


-- -------------------------------------------------------------
-- 3. Contributors Table
-- -------------------------------------------------------------
CREATE TABLE public.contributors (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name text NOT NULL,
    year text NOT NULL,
    department text NOT NULL,
    role text NOT NULL,
    avatar_url text DEFAULT 'https://i.pravatar.cc/150',
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL
);

-- Enable Row Level Security (RLS)
ALTER TABLE public.contributors ENABLE ROW LEVEL SECURITY;

-- RLS Policies
CREATE POLICY "Allow public read access for contributors" 
    ON public.contributors FOR SELECT TO public USING (true);

CREATE POLICY "Allow authenticated admin writes for contributors" 
    ON public.contributors FOR ALL TO authenticated USING (true);

-- -------------------------------------------------------------
-- 4. Feedbacks Table
-- -------------------------------------------------------------
CREATE TABLE public.feedbacks (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name text NOT NULL,
    year text NOT NULL,
    department text NOT NULL,
    event text,
    rating integer,
    message text NOT NULL,
    created_at timestamp with time zone DEFAULT timezone('utc'::text, now()) NOT NULL
);

ALTER TABLE public.feedbacks ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Allow public read access for feedbacks"
    ON public.feedbacks FOR SELECT TO public USING (true);

CREATE POLICY "Allow authenticated admin writes for feedbacks"
    ON public.feedbacks FOR ALL TO authenticated USING (true);

-- Allow anyone (public/anon) to insert feedback rows so visitors can submit feedback without auth
CREATE POLICY "Allow public inserts for feedbacks"
    ON public.feedbacks FOR INSERT TO public WITH CHECK (true);

-- -------------------------------------------------------------
-- 5. Seed Initial Data
-- -------------------------------------------------------------
INSERT INTO public.magazines (title, year, month, cover_image, pdf_url)

INSERT INTO public.words (word, meaning, example)
```

-- -------------------------------------------------------------
-- 6. Thoughts Table (singleton row for current thought)
-- -------------------------------------------------------------
-- This table stores the current Thought for the Week. Admins can upsert the single row with id = 'current'.
CREATE TABLE public.thoughts (
    id text PRIMARY KEY,

4. Click **Run** in the top-right of the SQL editor to execute the statements. You should see a success message.

## 3. Create Admin User (Authentication)

To log into your website's Admin Dashboard, you need to create an email-and-password user inside Supabase Auth:

1. Click on **Authentication** (User icon) in the left sidebar of your Supabase Dashboard.
2. Click **Add User** -> **Create User**.
3. Enter the email address and password you want to use for the Admin account (e.g., `admin@blueskyforum.com` and a strong password).
4. **Important**: Toggle the option to **Auto-confirm User** so that the email address is marked as verified immediately without needing email confirmation.
5. Click **Create User**.

You can now use this email and password combination to securely log into the website's `/admin` dashboard!
